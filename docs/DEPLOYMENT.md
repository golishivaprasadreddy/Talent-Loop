# Deployment

TalentLoop is configured for Vercel deployment and GitHub Actions CI/CD.

## Vercel

1. Push the project to GitHub.
2. Import the repository in Vercel.
3. Keep the detected Next.js settings.
4. Add production environment variables in Vercel.
5. Deploy.

## Required Production Environment

| Variable | Description |
| --- | --- |
| `MONGODB_URI` | Production MongoDB connection string |
| `JWT_SECRET` | Long random signing secret |
| `NEXT_PUBLIC_BASE_URL` | Production app URL |

Optional:

| Variable | Description |
| --- | --- |
| `OPENAI_API_KEY` | Enables OpenAI-backed AI routes |
| `OPENAI_MODEL` | Overrides the default AI model |

## GitHub Actions

The repository includes two workflows:

| Workflow | Trigger | Purpose |
| --- | --- | --- |
| `.github/workflows/ci.yml` | Pull requests and pushes to `main` | Install dependencies, run syntax check, and build |
| `.github/workflows/deploy.yml` | Pushes to `main` | Build and deploy production output to Vercel |

## GitHub Secrets for Deployment

Set these repository secrets for the deploy workflow:

| Secret | Source |
| --- | --- |
| `VERCEL_TOKEN` | Vercel account token |
| `VERCEL_ORG_ID` | Vercel project settings |
| `VERCEL_PROJECT_ID` | Vercel project settings |
| `MONGODB_URI` | MongoDB provider |
| `JWT_SECRET` | Generated by the project owner |

The workflows provide dummy values for build-time checks when secrets are absent, but production runtime features need real values in Vercel.

## Build Commands

```bash
npm ci
npm run lint
npm run build
```

Vercel uses:

```bash
npx vercel@latest build --prod
npx vercel@latest deploy --prebuilt --prod
```

## Production Checklist

- Use a strong `JWT_SECRET`.
- Restrict MongoDB network access to trusted hosts.
- Configure `NEXT_PUBLIC_BASE_URL` to the final HTTPS URL.
- Add an email provider for password reset delivery.
- Avoid using the default seeded admin password outside local development.
- Enable `OPENAI_API_KEY` only if AI features are intended for production.
